# Collaborative Design Principle

The framework assumes the best work emerges from explicit collaboration between design, engineering, QA, production, and release.

## Principle

Create artifacts that other disciplines can actually use.

A good document or implementation output should make the next collaborator faster, not merely look complete in isolation.

## What This Means in Practice

- design docs should expose dependencies and acceptance criteria
- architecture docs should explain consequences and boundaries
- implementation work should stay traceable to the decision that justified it
- QA and release docs should make risk visible early, not only at the end

## Preferred Behavior

- surface tradeoffs
- write down decisions once they matter again later
- keep disciplines in sync through explicit artifacts, not memory alone
